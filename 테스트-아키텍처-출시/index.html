테스트 · 아키텍처 · 출시

kotest 6.2 문서 · MockK README · Alistair Cockburn 의 헥사고날 원문(2005)과 AWS 헥사고날 안내서 · ArchUnit 사용자 가이드 · Pete Hodgson 「Feature Toggles」 · OpenFeature 문서를 따라가는 학습 문서. Kotlin 이나 Java 로 서버를 만들고 JUnit 으로 단위 테스트를 써 본 개발자를 전제로 한다. 0편(지도)을 먼저 읽고 필요한 편을 골라 읽는다.

  • 0편 다섯 주제 지도 — 테스트 · 아키텍처 · 출시다섯 주제는 저마다 어떤 문제를 풀고, Kotlin 서버 하나 안에서 서로 어디에서 만나나
  • 1편 kotest — 세 모듈로 나뉜 Kotlin 테스트스펙 스타일 · matcher · property 테스트로 테스트를 어떤 모양으로 쓰고, 쓸 때 무엇을 조심하나
  • 2편 MockK — 협력자 mock과 호출 검증Kotlin 코드의 협력자를 mock 으로 바꾸고 호출을 검증하는 법, 무엇은 mock 하지 말아야 하나
  • 3편 헥사고날 아키텍처 — 포트와 어댑터로 바깥 떼기애플리케이션을 UI · DB 같은 바깥 기술에서 어떻게 떼어 놓고, 그 대가로 무엇을 치르나
  • 4편 ArchUnit — 아키텍처 규칙 테스트패키지 · 레이어 의존 같은 아키텍처 규칙을 테스트 코드로 적고 지키는 법, 무엇은 잡지 못하나
  • 5편 피처 플래그 — 배포와 출시의 분리배포와 출시를 어떻게 떼어 놓고, 플래그 종류마다 어떻게 다루며, 늘어난 플래그가 무엇을 비용으로 남기나
