TDD 규율은 테스트를 코드보다 몇 초 앞서 쓰며 테스트와 코드를 촘촘한 고리로 번갈아 쓰는 작업 방식이다. 저자는 이 규율을 20년 넘게 Java · C · Ruby · Clojure 같은 여러 언어에서 지켜 왔고, 규율은 언어와 상관없이 같다고 단정한다.

이 책의 테스트는 대부분 Ruby 의 RSpec 과 비슷한 테스트 틀 speclj 로 썼다. describe 가 JUnit 의 테스트 클래스, it 이 테스트 메서드 자리에 선다.

mock — 함수를 잠시 바꿔 끼워 대역을 세운다

여기서 읽을 것 — mock 을 못 쓴다는 통설이 어디서 왔는지, 그리고 다형 인터페이스 없이 대역이 어떻게 서는지 읽는다.

mock 을 못 쓴다는 통설은 LSP 를 객체지향 원칙으로 보고 mock 을 다형 인터페이스 위에 세우던 데서 생겼다. 저자는 LSP 가 함수형에서도 똑같이 서고 다형 인터페이스도 쉽게 만드니 mock 도 막히지 않는다고 답한다.

정의 stub — 아무것도 하지 않고 불린 일만 기억하는 대역

stub 은 인자를 몇 개든 받고 아무것도 돌려주지 않지만, 자기에게 무슨 일이 일어났는지는 기억한다. 저자의 각주대로 엄밀히는 spy 라, Mockito 로 치면 mock 보다 spy 에 가깝다.

저자는 이 테스트가 무엇을 하는지는 신경 쓰지 말고 with-redefs 만 보라고 한다. 그 한 줄이 인터페이스 없이 함수 두 개를 잠시 바꿔 끼워 대역을 세우는 자리다.

(defn update-position
  [{:keys [position velocity heading distance] :as turtle}]
  (let [step (min (q/abs velocity) distance)
        distance (- distance step)
        step (if (neg? velocity) (- step) step)
        radians (q/radians heading)
        [x y] position
        vx (* step (Math/cos radians))
        vy (* step (Math/sin radians))
        position [(+ x vx) (+ y vy)]]
    (assoc turtle :position position
                  :distance distance
                  :velocity (if (zero? distance) 0.0 velocity))))

(defn update-heading [{:keys [heading omega angle] :as turtle}]
  (let [angle-step (min (q/abs omega) angle)
        angle (- angle angle-step)
        angle-step (if (neg? omega) (- angle-step) angle-step)
        heading (mod (+ heading angle-step) 360)]
    (assoc turtle :heading heading
                  :angle angle
                  :omega (if (zero? angle) 0.0 omega))))

답이 난 것
  • 함수형으로 짜면 테스트 규율과 화면 부작용에서 달라지는 것은 어디까지인가(이 문서의 물음) 테스트 규율은 그대로이고 속성 기반 테스트라는 진단 도구가 더해진다. 화면을 바꾸는 부작용은 남되 갱신 루프의 끝으로 몰리고, 스크립트의 부작용은 채널에 넣기 하나로 준다.
  • REPL 에서 다 시험하면 TDD 가 필요 없는가 아니다 — REPL 의 실험은 다음 날 남지 않아 배운 것은 테스트로 옮긴다.
  • 함수형 언어는 mock 을 못 쓰는가 도시 전설이다 — 함수를 잠시 바꿔 끼워 대역을 세운다.
  • 거북 그래픽 틀은 함수형인가 순수하지는 않아도 꼬리 호출 최적화 시스템만큼은 함수형이다.
답이 나지 않은 것과 이어지는 곳
  • 속성 기반 테스트는 TDD 의 반론인가 저자가 편들지도 반박하지도 않겠다고 했고, 다룰 곳을 밝히지 않았다
  • 가변 시스템에서 속성 기반 테스트는 얼마나 복잡한가 저자가 짐작만 하고 다룰 곳을 밝히지 않았다

  • test.check 생성기의 세부 Clojure 의 test.check 입문 안내(원문 각주 8)
  • Quil 을 제대로 쓰는 법 Quil 누리집(원문 각주 1)
